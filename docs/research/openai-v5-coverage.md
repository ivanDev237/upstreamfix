# openai-node v4 → v5 migration coverage

Source of truth: [official `MIGRATION.md` at the v5.0.0 release commit](https://github.com/openai/openai-node/blob/524080c001a22998cf12b91025187f6993fc66dc/MIGRATION.md) (`524080c001a22998cf12b91025187f6993fc66dc`). This document concerns **v5.0.0**, not the current SDK guide, which can change. “Manual” means an explicit finding that blocks an automatic package upgrade; it is not a claim that the tool can fix the behavior. The guide's migration CLI is an upstream tool, not an SDK breaking change.

## Promotion status

**Experimental.** The matrix records the official guide and identifies unresolved detection gaps in indirect values and runtime inference. Promotion additionally requires the benchmark of at least 15 valid public repositories, at least 10 repositories with relevant usages, each rule represented, >=80% automatic migration, zero corrupt files, no unexplained typecheck regression, real v5 SDK tests for each rule, and a report from the PR head. The first 15-repository GitHub measurement ([run 39506284925](https://github.com/ivanDev237/upstreamfix/actions/runs/39506284925), source SHA `102941480f57bf123553038879b3243b21f619d8`) reached 24.2% (8/33) and found three lockfile installations that fail before migration. Those three are now retained as documented invalid repositories while five more pinned candidates bring the corpus to 17 potentially valid projects. This expanded corpus still needs a completed GitHub measurement. The committed benchmark report still covers seven repositories and must not be presented as promotion evidence.
